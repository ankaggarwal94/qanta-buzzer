# Cryptographic Artifact Provenance With Runtime Verification

## Context

`paper_exports/audit_card.md` is the headline scientific evidence cited by the final-project manuscript: a three-row verdict table (CSLI / Calibration / StopDFF) computed by `scripts/make_audit_card.py` from three committed JSON artifacts produced by three independent scripts (`compute_csli.py`, `compute_prefix_calibration.py`, `compute_stopdff.py`). Before PR #14 round 11 only `csli.json` carried a lone `git_commit` string in its metadata; `calibration.json`, `stopdff.json`, and `audit_card.json` had no provenance fields at all. ChatGPT-5.5 Pro's review Blocker 4 named the gap directly: committed JSONs could silently drift from producer code (someone edits `compute_stopdff.py` without re-running it, the per-file diff hides the staleness, the audit card keeps publishing the verdict). For frozen-threshold workflows where artifacts persist across many commits this is the highest-risk class of failure: the numbers *look* fresh because they are tracked, but they are no longer tied to the code that supposedly produced them.

The companion `producer-emitted-flags-without-consumer-propagation` pattern fixed *semantic* drift (the producer detected a degenerate run but the consumer ignored the flag). This pattern fixes *artifact-source* drift (the consumer cannot tell whether the producer JSON was generated by the same code currently on disk). Both axes need to be machine-checked.

## Guidance

Three-part pattern:

1. **One shared helper** in `scripts/_common.py` builds a schema-versioned `generation` block carrying the script's file-content SHA-256, the git commit at write time, an explicit `git_dirty` flag scoped to relevant inputs, the effective argv, and the timestamp.
2. **Every producer** calls the helper at write time and embeds the result under `metadata.generation` in its JSON output.
3. **The aggregator** recomputes each producer's live SHA-256 at runtime, compares to the recorded value, and renders a yes/no match table in the human-readable audit card.

### The shared helper

```python
# scripts/_common.py
def build_generation_provenance(
    script_path: str | Path,
    argv: list[str],
    *,
    output_path: str | Path,
    extra_paths: list[str | Path] | None = None,
) -> dict[str, Any]:
    script_resolved = Path(script_path).resolve()

    # Render every path for the operator-facing `output_path` field, but
    # FILTER non-repo paths from the git pathspec — `git status -- <abs_path>`
    # aborts with `fatal: ... is outside repository` when any pathspec arg
    # is outside the repo, which would silently flip `git_dirty` to False.
    display_paths = [
        project_relative(script_resolved),
        project_relative(output_path),
    ]
    for p in extra_paths or []:
        display_paths.append(project_relative(p))
    repo_relative_pathspec = [p for p in display_paths if not Path(p).is_absolute()]

    status_args = ["status", "--short", "--", *repo_relative_pathspec]
    git_status = _git_output(status_args)

    # Prefer host-injected SHA via env var (for tool-poor container
    # runtimes that lack the `git` binary); fall back to live query.
    host_commit_env = os.environ.get("MODAL_HOST_GIT_COMMIT")
    git_commit = host_commit_env if host_commit_env else _git_output(["rev-parse", "HEAD"])

    return {
        "schema_version": 1,
        "generated_at_utc": datetime.now(timezone.utc).isoformat(),
        "command": ["python", project_relative(script_resolved), *argv],
        "argv": list(argv),
        "cwd": project_relative(Path.cwd()),
        "output_path": project_relative(output_path),
        "script_path": project_relative(script_resolved),
        "script_sha256": sha256_file(script_resolved),
        "git_commit": git_commit,
        "git_dirty": bool(git_status),
        "git_status_relevant_paths": git_status or "",
    }
```

Four design choices matter:

- **`script_sha256` is a file-content hash, not a git blob hash.** That makes it meaningful even for uncommitted edits (paired with `git_dirty: true` to flag in-flight runs).
- **`git status --short -- <repo-relative pathspec>`** scopes the dirty signal to files this artifact actually depends on AND filters out-of-repo absolute output paths so `git status` cannot abort with `fatal: outside repository` (a Codex #3308590294-class failure mode for the absolute `--output-dir` round-trip case). The filter retains every path in `output_path` display fields while skipping non-repo entries in the git pathspec.
- **`extra_paths`** lets each producer declare its real input dependencies so the scoping is accurate.
- **`MODAL_HOST_GIT_COMMIT` env-var preference** — when the producer runs inside a container that lacks the `git` binary (e.g., Modal `debian_slim`), the live `git rev-parse HEAD` query returns None and `git_commit` would record as empty. The orchestrator computes the host SHA at submit time and injects it via env var; the helper prefers the env var over the live query. This is a transport-layer concern handled by the sibling `host-injected-provenance-for-tool-poor-containers` pattern; the contract (filling the `git_commit` field) stays the same.

### Producer call site

```python
# scripts/compute_stopdff.py
from scripts._common import build_generation_provenance

generation = build_generation_provenance(
    __file__,
    effective_argv,
    output_path=output_path,
    extra_paths=[THRESHOLD_MANIFEST, data_dir / "build_metadata.json", calibration_path],
)
output["metadata"]["generation"] = generation
```

`effective_argv` is captured *before* `_parse_args` mutates `sys.argv` so the provenance records the actual invocation, not a post-parse echo.

### Aggregator runtime check

```python
# scripts/make_audit_card.py
def _build_artifact_provenance(csli_data, cal_data, stopdff_data) -> dict:
    sources = {
        "csli.json":        (csli_data,    REPO_ROOT / "scripts/compute_csli.py"),
        "calibration.json": (cal_data,     REPO_ROOT / "scripts/compute_prefix_calibration.py"),
        "stopdff.json":     (stopdff_data, REPO_ROOT / "scripts/compute_stopdff.py"),
    }
    out = {}
    for name, (data, script_path) in sources.items():
        gen = (data.get("metadata") or {}).get("generation") or {}
        recorded_sha = gen.get("script_sha256")
        current_sha = sha256_file(script_path) if script_path.exists() else None
        if recorded_sha is None or current_sha is None:
            match = None
        else:
            match = recorded_sha == current_sha
        out[name] = {
            "recorded_commit": gen.get("git_commit"),
            "recorded_sha256": recorded_sha,
            "current_sha256": current_sha,
            "sha_matches": match,
        }
    return out
```

The verification is **read-only and non-fatal** — a mismatch becomes a visible `no` row in the rendered markdown table rather than a hard error. The audit card always renders; the reader sees the mismatch and decides what to do. A `WARNING:` is also emitted to stderr so CI logs surface the drift.

## Why This Matters

Without runtime provenance enforcement:

- **Silent drift.** A producer is edited but not re-run. The committed JSON and the producer source no longer match. The reviewer sees both and has no fast way to detect the mismatch.
- **Wrong verdict published.** The aggregator's verdict cell is computed from numbers the current code would not produce. The manuscript cites a stale claim. A peer reviewer would need to check out the recorded commit, re-run the producer, and diff the JSON to catch it. Most reviewers won't.
- **No 30-second audit.** Reproducing a headline number requires manual archaeology. Most readers stop at the table.

With the pattern in place, opening `paper_exports/audit_card.md` shows a three-row SHA-match table:

```
## Artifact Provenance — Source Script SHA-256 Match

| Source Artifact  | Recorded commit | Recorded sha256 | Current sha256 | Match |
|------------------|-----------------|------------------|------------------|-------|
| csli.json        | f5600efeb744    | 781621353c06     | 781621353c06     | yes   |
| calibration.json | f5600efeb744    | 101a2f20350b     | 101a2f20350b     | yes   |
| stopdff.json     | f5600efeb744    | 09709d1cca3f     | 09709d1cca3f     | yes   |
```

`yes` everywhere means the committed numbers came from the committed code at the committed commit. The reviewer's integrity audit is one glance.

A subtle bonus: `git_dirty: true` plus a non-empty `git_status_relevant_paths` flags the *opposite* failure mode — the JSON was generated from uncommitted edits. The SHA will match the working tree but the dirty flag makes the situation explicit.

## When to Apply

- **Multi-script audit pipelines** where N producers feed one aggregator that publishes a downstream verdict.
- **Manuscript-cited verdicts.** Anything a reader will quote, a peer reviewer will check, or a re-implementer will reproduce.
- **Frozen-threshold or frozen-split workflows.** When the same JSONs persist across dozens of commits, file timestamps and surrounding diffs no longer prove freshness.
- **Multi-agent or multi-committer environments.** Anyone — human or agent — can edit a producer in isolation, so trust must be machine-checkable rather than social.

Skip the pattern when (a) the aggregator regenerates inputs on every run (no staleness window exists), or (b) the artifacts are throwaway logs not cited downstream.

## Examples

### Before / after, one producer

Before — no provenance:

```python
output = {
    "verdict": gate_verdict,
    "median_abs_prefix_shift": median_abs_prefix_shift,
    "metadata": {"timestamp": datetime.now(timezone.utc).isoformat()},
}
json.dump(output, f)
```

After — one helper call, one field set:

```python
from scripts._common import build_generation_provenance

generation = build_generation_provenance(
    __file__, effective_argv, output_path=output_path,
    extra_paths=[THRESHOLD_MANIFEST, data_dir / "build_metadata.json", calibration_path],
)
output = {
    "verdict": gate_verdict,
    "median_abs_prefix_shift": median_abs_prefix_shift,
    "metadata": {
        "timestamp": datetime.now(timezone.utc).isoformat(),
        "generation": generation,
    },
}
json.dump(output, f)
```

### Contract-pinning test

```python
# tests/test_pr14_review_regressions.py
def test_artifact_provenance_block_flags_stale_artifacts(tmp_path):
    csli_data = {"metadata": {"generation": {
        "script_sha256": "deadbeef" * 8,
        "git_commit": "abc1234abc1234abc1234abc1234abc1234abcd",
        "script_path": "scripts/compute_csli.py",
    }}}
    # cal_data and stopdff_data follow the same shape with intentionally wrong hashes.

    provenance = make_audit_card._build_artifact_provenance(csli_data, cal_data, stopdff_data)

    for name in ("csli.json", "calibration.json", "stopdff.json"):
        block = provenance[name]
        if block["current_sha256"] is not None:
            assert block["sha_matches"] is False
```

A sibling test (`test_artifact_provenance_renders_markdown_section`) pins the rendered table format so a future refactor cannot silently drop the section.
