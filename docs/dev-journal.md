## 2026-08-18 — Hazard-Pretrain Efficacy Eval Harness

Built the controlled experiment that answers whether PR #32's hazard warm-start bridge helps the T5 buzz policy. Two small enablers landed first: `--seed` on `scripts/train_t5_policy.py` (re-seeds random/numpy/torch immediately before EACH phase — a single top-of-main seed provably fails the RED test, which scrambles RNG state between phases) and `evaluate_t5_policy(return_runs=True)` in `scripts/compare_policies.py` (per-question records keyed by qid, sharing the aggregates' policy-buzz source of truth). The bridge itself gained `ablation="shuffled_nll"` (a step-matched null-signal control using a dedicated torch.Generator so T=1 questions reproduce non-ablated losses bitwise) and `hazard_history.json` instrumentation (per-step losses + hazard-phase wall-clock).

`scripts/run_hazard_efficacy.py` (~4k lines) is the orchestrator: one shared supervised checkpoint (built with `--ppo-iterations 1 --skip-test-eval`), arm plans round-tripped through the real child parser at preflight, subprocess children via a single injectable `_run_child` seam (tee to train.log, PYTHONUNBUFFERED, output-staleness watchdog), identity-validated resume (RUN_COMPLETE.json markers carry arm/seed/smoke/wall-clock/shared-checkpoint weight fingerprint; resumed dirs are re-validated against THIS invocation's plan — hazard knobs included), a single verify_run_records() gate shared by the execute and --report-only paths, per-run eval_result.json written immediately after each eval, and a schema_version-1 report with a scale block, verbatim Device-2 caveat, pre-committed falsifiable endpoint, and paired-by-qid bootstrap significance that hard-gates below 50 test questions. Reuse pins: evaluate_t5_policy and evaluation.controls.bootstrap_ci are identity-imported (tests assert `is`-level/provenance equality).

Notable design decisions: exemption-from-equality is not identity (the arm-control diff exempts hazard/seed keys, so those exact keys are separately asserted per-run against the PLAN — the mini-audit's top finding); completion markers are invalidate-before-mutate and atomically written; prune (--prune-checkpoints) fires per-run right after eval and excludes optimizer state from the weight fingerprint so pruned shared checkpoints still reuse. The non-smoke split resolution gotcha (artifacts/main absent -> silent artifacts/smoke fallback) burned one calibration run and is now documented in AGENT_CONTEXT pitfalls + AGENTS.md.

The science: at both tested scales the default beta=1.0 bridge collapses the stop head to never-buzz (hazard loss converges to exactly beta = the pure-survival corner), PPO never recovers, and the C ablation reproduces B to 4 decimals — the bridge's effect is objective-shape pressure with zero temporal signal, because the tested answer heads have flat per-position NLL. beta=2.0 flips to the other corner (always-buzz-at-0). Full mechanism, dose-response table, and the diagnostic-first Device-2 recommendation: docs/hazard-efficacy-report.md.

## 2026-08-19 — Camera-Ready AIMS Evidence Flow

**What was built.** A self-contained, fail-closed evidence verifier under `reproducibility/colm_aims_2026/` supporting the COLM 2026 AIMS workshop paper. The paper's defensible claim is a *constructed-reference sensitivity audit* — it does not establish that multiple-choice evaluation preserves an observed open-ended stopping policy — so the whole namespace is built to make that negative-result claim independently checkable without ever letting a stronger claim slip through. It composes with the existing StopDFF v5 fail-closed/create-once contract family (`scripts/stopdff_v5/fileio.py`, `bootstrap.py`) rather than reinventing it, and leaves the legacy `scripts/verify_audit_release.py` byte-identical.

**Code written.** Seven modules (~5,000 LOC): `schema.py` (strict schema-versioned profile validation, typed ingress, the bounded-regular-file reader, create-once publish), `pairing.py` (the five pair/censoring count identities, timeout boundary, key-set discipline, estimand digest, historical-estimator parity via `stopdff_v5.bootstrap.cell_bootstrap_stats`), `verifier.py` (the two-mode engine — a declarative `REQUIRED_PROVENANCE_FIELDS` table drives the release binding legs, plus ledger recompute, manifest reconciliation, snapshot-then-verify tree loading, and the estimand-reconciliation leg), `ledger.py` (claim-ledger + rights inventory with closed enums), `receipt.py` (create-once run-scoped receipts), `render.py` (vocabulary-disciplined summaries), and `verify.py` (the CLI with `allow_abbrev=False` and pinned exit codes 0–4). Plus a shipped honest `ledger.json`, a namespace `README.md`, and ~880 lines of test helpers driving 595 tests across 12 test files. The `reproducibility/source_to_claim.md` map gained a historical-scope header.

**How it works.** Release certification is deliberately *not* self-attesting: expectations must live symlink-free outside the verified tree and anchor to a reviewed commit + the frozen ledger, so an artifact plus its own generated manifest tops out at `PASS_SOURCE_ONLY`. Every binding is checked twice — admissible in its own right (reject `UNRESOLVED`/empty/mutable-model-identity) *and* equal to the anchored expectation — via a shared `_check_binding` helper backed by a validator registry. The tree is read once into an in-memory snapshot that drives content validation, every gate hash, and the receipt digest, so the receipt provably attests exactly the gated bytes; symlinked members are refused rather than followed. Fabricated estimand fields (calibration identity, denominator policy, timeout params, arm ids, Random-K draw id) are reconciled against their authoritative sources, so a substituted favorable Random-K draw fails rather than passing through a self-recomputed digest.

**Non-obvious decisions and what the review process caught.** The detector recommended `high` intensity; the author set `standard`. The two QA rounds surfaced a systematic soft spot — release legs were mirror-equality against expectations derived from the artifact itself — and closed it with re-derivation-from-source-of-truth as a standing class fix (substitution-negative tests, a validator-registry meta-test). The 8-lens mini-audit then found what QA structurally couldn't: three CRITICAL DoS/containment holes (unbounded `draw_count` → bootstrap OOM, FIFO/`/dev/stdin` at `--expectations`, symlinked tree members hashed from outside the tree with a dead `tree_resolved` guard sitting right there) and seven HIGH release-integrity/entrypoint issues (the referenced-path containment gap that let the "independent" anchor collapse into the verified tree; the `verify.py` sys.path membership-guard anti-pattern PR #30 removed; the git object-existence check reading ambient `cwd`/`GIT_DIR`; containment tests that would have failed the PR's own CI on a shallow clone). All were fixed in a third round and re-audited CLEAN. Key durable lesson (mirrors the repo's PR #41 history): a fail-closed verifier's *perimeter* can be immaculate while its *interior* certifies against author-controlled proxies — adversarial lenses that construct hostile artifacts, not just green tests, are what expose that.
