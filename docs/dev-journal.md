# Dev Journal

## 2026-08-18 — Hazard-Pretrain Efficacy Eval Harness

Built the controlled experiment that answers whether PR #32's hazard warm-start bridge helps the T5 buzz policy. Two small enablers landed first: `--seed` on `scripts/train_t5_policy.py` (re-seeds random/numpy/torch immediately before EACH phase — a single top-of-main seed provably fails the RED test, which scrambles RNG state between phases) and `evaluate_t5_policy(return_runs=True)` in `scripts/compare_policies.py` (per-question records keyed by qid, sharing the aggregates' policy-buzz source of truth). The bridge itself gained `ablation="shuffled_nll"` (a step-matched null-signal control using a dedicated torch.Generator so T=1 questions reproduce non-ablated losses bitwise) and `hazard_history.json` instrumentation (per-step losses + hazard-phase wall-clock).

`scripts/run_hazard_efficacy.py` (~4k lines) is the orchestrator: one shared supervised checkpoint (built with `--ppo-iterations 1 --skip-test-eval`), arm plans round-tripped through the real child parser at preflight, subprocess children via a single injectable `_run_child` seam (tee to train.log, PYTHONUNBUFFERED, output-staleness watchdog), identity-validated resume (RUN_COMPLETE.json markers carry arm/seed/smoke/wall-clock/shared-checkpoint weight fingerprint; resumed dirs are re-validated against THIS invocation's plan — hazard knobs included), a single verify_run_records() gate shared by the execute and --report-only paths, per-run eval_result.json written immediately after each eval, and a schema_version-1 report with a scale block, verbatim Device-2 caveat, pre-committed falsifiable endpoint, and paired-by-qid bootstrap significance that hard-gates below 50 test questions. Reuse pins: evaluate_t5_policy and evaluation.controls.bootstrap_ci are identity-imported (tests assert `is`-level/provenance equality).

Notable design decisions: exemption-from-equality is not identity (the arm-control diff exempts hazard/seed keys, so those exact keys are separately asserted per-run against the PLAN — the mini-audit's top finding); completion markers are invalidate-before-mutate and atomically written; prune (--prune-checkpoints) fires per-run right after eval and excludes optimizer state from the weight fingerprint so pruned shared checkpoints still reuse. The non-smoke split resolution gotcha (artifacts/main absent -> silent artifacts/smoke fallback) burned one calibration run and is now documented in AGENT_CONTEXT pitfalls + AGENTS.md.

The science: at both tested scales the default beta=1.0 bridge collapses the stop head to never-buzz (hazard loss converges to exactly beta = the pure-survival corner), PPO never recovers, and the C ablation reproduces B to 4 decimals — the bridge's effect is objective-shape pressure with zero temporal signal, because the tested answer heads have flat per-position NLL. beta=2.0 flips to the other corner (always-buzz-at-0). Full mechanism, dose-response table, and the diagnostic-first Device-2 recommendation: docs/hazard-efficacy-report.md.
