# Spec: Hazard-Pretrain Efficacy Eval Harness

## Metadata
- **Task**: hazard-efficacy-eval
- **Recommended-intensity**: standard
- **Intensity**: standard
- **Intensity reason**: no security/`hooks/`/TB-xxx signals (no TB entries exist — dormant); antipatterns/QA history empty (dormant); no security keywords
- **Override**: none
- **Branch**: feature/hazard-efficacy-eval
- **Source**: adopted from `.planning/hazard-eval-harness-spec.md` (pre-hardened by a two-critic pass — experimental-validity + RL-metrics/feasibility — grounded in the real code). Prepared-spec rule IDs R-1..R-8 and enablers E-1/E-2 map to the R-xxx rules below as noted. Revised per /creview findings RV-001..RV-009 and UX subagent findings UX-001..UX-008 (see `.correctless/artifacts/reviews/review-findings-hazard-efficacy-eval.md`).

## What

Quantify whether the `--hazard-pretrain` warm-start bridge (PR #32, smoke-validated as plumbing only) actually improves the T5 buzz policy. A thin orchestration harness (`scripts/run_hazard_efficacy.py`) runs a paired WITH/WITHOUT/compute-control comparison: one shared supervised checkpoint branches into Arm A (control: no hazard), Arm B (treatment: `--hazard-pretrain`, ± knob variants `--beta-terminal`, `--freeze-answer-head`) and Arm C (step-matched signal-free hazard ablation), each × training seeds 1/2/3, all evaluated through the identical `evaluate_t5_policy` path on the same test split. Both arms are the SAME T5-policy architecture → strictly apples-to-apples (the `compare_policies.py` by-architecture S_q caveat does not apply). Two small code enablers must land first or the comparison is invalid: **E-1** a training `--seed` (training is unseeded today) and **E-2** per-question eval surfacing (per-question S_q/buzz are discarded locals today). Output: `hazard_efficacy_report.json` (per arm×seed metrics + A/B/C deltas + verdict + scale caveat) plus a buzz-position/accuracy plot. Runs on Device 1 (M3 Max, MPS): smoke (t5-small) for plumbing + training dynamics, t5-base for the preliminary efficacy signal; full-scale t5-large stays a Device-2 (RTX 5090) run.

## Rules

Test level guide: [unit] = isolatable logic; [integration] = wiring through the real system path.

- **R-001** [integration] (enabler E-1, prepared-spec E-1): `scripts/train_t5_policy.py` gains `--seed <int>` (default None = current unseeded behavior). When set, it seeds Python `random`, NumPy, and torch **before each** training phase (supervised / hazard / PPO), is recorded as a top-level `seed` key in the saved `config_used.json`, and is **separate from `data.seed`** (which drives only the split). With the data split held fixed: two different `--seed` values produce different training-phase RNG draws (proxy: a monkeypatched trainer capturing `torch.rand`/`random.random` at call time sees different values across seeds, identical values across re-runs of the same seed), while the split manifest train/val/test qids are identical across seeds.
  Entry: `main()` with monkeypatched `run_supervised_training`/`run_hazard_pretrain`/`run_ppo_training` (pattern: `tests/test_train_t5_policy_script.py`; patches target the lazy-import source modules).
  Through: real `parse_args`/`load_config_with_overrides`/`load_question_splits_with_metadata`; the seeding helper must NOT be mocked.
  Exit: captured RNG draws differ across `--seed 1` vs `--seed 2`, match across two `--seed 1` runs; `split_manifest` qids identical in all cases; `config_used.json` records the seed.

- **R-002** [integration] (enabler E-2, prepared-spec E-2): `evaluate_t5_policy` gains keyword-only `return_runs: bool = False`. When True, the returned dict additionally carries `"runs"`: one record per evaluated question with at least `{qid, sq, buzz_position (int | None), buzzed (bool — policy buzz), correct (bool), forced_correct (bool), confidence (float | None — top_p at decision), episode_reward (float), n_steps (int)}` (mirrors the `summary["runs"] = runs` pattern of `evaluation/controls.py`). Default False leaves the existing payload unchanged (backward compatible). Aggregates must be consistent: `mean_sq == mean(runs[].sq)` and `avg_buzz_pos == mean` of the recorded buzz positions.
  Entry: `evaluate_t5_policy` on a tiny fixture checkpoint + ≥2-question fixture (pattern: existing `tests/test_compare_policies.py`).
  Through: real `TossupMCEnv` + `TextObservationWrapper` episode loop; metrics functions not mocked.
  Exit: `runs` records present, one per question, aggregate-consistent; absent when `return_runs` omitted.

- **R-003** [integration] (prepared-spec R-1 controlled arms; amended per RV-001): The harness runs the supervised warm-start ONCE, then every arm×seed branches from it via `--skip-supervised --model-path <shared_sup_ckpt>`; identical `model_name`, data split, PPO budget across arms; only Phase 1.5 (and `--seed` across seed replicas) differs. `scripts/train_t5_policy.py::main` records a `hazard` block `{pretrain: bool, beta_terminal: float, freeze_answer_head: bool, ablation: str|null}` plus the top-level `seed` into `config_used.json` so every run dir is self-describing. The harness **asserts** arm control by diffing each arm×seed's `config_used.json` — all keys must be equal EXCEPT exactly the `hazard` block, `seed`, and checkpoint-dir keys — and asserting identical `split_manifest.json` train/val/test qids across all runs; any mismatch fails loud (nonzero exit, no report written).
  Entry: harness assertion stage against stub run dirs with doctored sidecars.
  Through: the real assertion code path reading real JSON sidecar files.
  Exit: doctored `model_name` or split qids → raised error naming the offending arm; clean sidecars → assertions pass.

- **R-004** [integration] (prepared-spec R-2 compute-confound control): `run_hazard_pretrain` gains keyword-only `ablation: str | None = None`; `ablation="shuffled_nll"` runs the identical loop (same question set, epochs, optimizer-step count as the real hazard phase) but permutes each question's per-prefix NLL vector across its T positions with a seeded RNG before the loss — destroying the temporal signal while preserving compute. `scripts/train_t5_policy.py` exposes `--hazard-ablation shuffled_nll` (requires `--hazard-pretrain`; rejected otherwise by `validate_args`). The report includes the C-vs-A and B-vs-A deltas side by side plus B's hazard optimizer-step count and wall-clock (the matching unit is optimizer steps; B=1-per-question steps are NOT commensurable with supervised B=N steps — stated in the report).
  Entry: `run_hazard_pretrain(..., ablation="shuffled_nll")` on t5-small CPU with a ≥2-prefix fixture question.
  Through: real training loop; loss/optimizer not mocked.
  Exit: same optimizer-step count as the non-ablated run on the same input; loss finite; permutation provably applied (a crafted position-dependent NLL pattern yields a different loss than unshuffled under a fixed ablation RNG).

- **R-005** [integration] (prepared-spec R-3 metrics, identical path; amended per RV-009): For each arm×seed the harness evaluates that run's checkpoint through the SAME `evaluate_t5_policy` call (with `return_runs=True`) on the SAME test split resolved from the shared split manifest, computing: accuracy, mean S_q (`evaluation/metrics.py::system_score`), `expected_calibration_error`, `brier_score`, buzz-position mean + histogram, plus per-run `policy_buzz_rate` and `forced_commit_rate` (derived from the E-2 runs) so a degenerate never-buzz/always-buzz policy is diagnosable from the report. **Expected Wins is EXCLUDED from the default** (`expected_wins_score` needs a mandatory `opponent_survival_trace` + the `reward_mode="expected_wins"` opponent wiring); it may only appear behind an explicit opt-in flag that wires that path — not built by default.
  Entry: harness eval stage with `evaluate_t5_policy` monkeypatched to record its call arguments.
  Through: real per-arm checkpoint-path resolution + test-split resolution from the manifest.
  Exit: one call per arm×seed; identical `test_questions` qid list and identical kwargs (except checkpoint path) across calls; no Expected Wins key in the default report.

- **R-006** [unit] (prepared-spec R-4 primary endpoint, falsifiable; amended per RV-004): The report computes the pre-committed primary endpoint: **treatment mean correct-answer buzz position ≤ control mean correct-answer buzz position − 1.0 prefixes AND `treatment_accuracy >= control_accuracy - 0.01` (absolute), replicated in ≥2 of 3 seeds.** Buzz-position comparison is conditioned on policy-buzz-and-correct episodes (raw mean buzz position co-varies with accuracy); the per-seed position×accuracy pairs are stored alongside the boolean so the frontier is auditable. A seed where EITHER arm has zero correct policy buzzes is a non-success for replication and its record carries `undefined_position: true`. S_q is the secondary composite endpoint.
  Test: pure function over synthetic per-seed run records → boolean + intermediate numbers exactly per the definition (edge cases: zero correct policy buzzes; exact-threshold ties).

- **R-007** [unit] (prepared-spec R-5 significance, scale-gated; amended per RV-008): Significance = paired-by-qid bootstrap CI on per-question S_q deltas. Pairing/pooling is defined as: average S_q over seeds within each arm per qid → per-qid delta (treatment − control) → bootstrap resampling over qids (per `evaluation/controls.py::bootstrap_ci` semantics). Per-seed CIs may be reported as secondary detail but never pooled as 3×n independent pairs. The report labels bootstrap CIs as a significance claim ONLY when the evaluated test set has ≥ 50 questions; below that (smoke ≈ 8 qs) the report sets `significance: "not_evaluable_at_this_scale"` and carries training-dynamics evidence instead. Seed-level n=3 mean±std is never labeled significant.
  Test: pure function — n≥50 synthetic paired runs → CI emitted with `significance_evaluable: true`; n<50 → gated label; unpaired/missing qids → fail loud.

- **R-008** [integration] (prepared-spec R-6 provenance fail-loud; amended per RV-007): Every arm×seed writes to a DISTINCT `checkpoint_dir` (the default `checkpoints/ppo_t5` collides — one dir per `flatten_config`'s single `checkpoint_dir`); the harness derives per-run dirs (e.g. `<out>/<arm>_seed<k>/`) and passes them via the `supervised.checkpoint_dir=` positional override. The report records per run: `model_name`, `seed`, `device`, git SHA, `git_dirty` (porcelain non-empty), torch version, platform string, and the config/split assertions of R-003. The shared supervised run persists a split manifest next to the supervised checkpoint (only PPO writes one today) so it is provable supervised never saw test qids (test ∩ supervised-train = ∅ asserted).
  Entry: harness dir-planning + provenance-assembly stage.
  Through: real filesystem layout + real `git rev-parse HEAD` / `git status --porcelain`.
  Exit: distinct dirs for every arm×seed; report provenance block complete or fail-loud (missing field → error, no report).

- **R-009** [unit] (prepared-spec R-7 scale caveat in output; amended per UX-007/UX-008): `hazard_efficacy_report.json` carries a top-level `schema_version` (integer, starts at 1), the harness checkout's git SHA, an `endpoint_definition` string restating the R-006 criterion, a structured `scale` block (`model_name`, n_train/n_val/n_test, ppo_iterations, device, measured total disk usage of the output tree) and a `caveats` list that ALWAYS includes the fixed sentence that full-scale t5-large efficacy remains a Device-2 (RTX 5090) run; the verdict is a structured object `{verdict, scope, evidence}` — never an unqualified "hazard helps" string. The plot is written to `<out>/hazard_efficacy_plot.png` via `savefig` (never `show()`); the report records the plot's relative path.
  Test: report-assembly function output contains `schema_version`, `endpoint_definition`, the scale block (incl. disk usage), the Device-2 caveat verbatim, the structured verdict, and the plot path, for both smoke and non-smoke inputs.

- **R-010** [integration] (handoff goal 2 + prepared-spec R-5 smoke portion — training dynamics; amended per RV-005): `run_hazard_pretrain` additionally records per-optimizer-step losses (epoch, question index, loss) and writes `hazard_history.json` into the hazard checkpoint parent dir (`<checkpoint_dir>/hazard/`), additively — the returned path and checkpoint format are unchanged and PPO consumption is unaffected. The harness computes, for the supervised vs hazard checkpoints, the stop-probability distribution — P(BUZZ) per prefix position, probed under `torch.no_grad()` with `model.eval()` (dropout off) over the DETERMINISTIC sample = first `min(32, len(train))` train questions in split order — and stores a shift summary (per-position means before/after + expected-buzz-time delta) in the report's `hazard_dynamics` block, together with first-vs-second-half mean loss from `hazard_history.json`.
  Entry: a real tiny t5-small CPU hazard run (module-scoped fixture pattern of `tests/test_hazard_pretrain.py`).
  Through: real training loop + real checkpoint save/load; probe not mocked.
  Exit: `hazard_history.json` exists with one record per optimizer step, all losses finite; the stop-prob probe returns per-position arrays of the right shape; the report block carries both dynamics fields. (Whether the loss actually decreases is a RUN RESULT reported by the harness, not a test assertion.)

- **R-011** [integration] (prepared-spec smoke-overrides requirement; amended per RV-006/UX-003/UX-004): At `ppo.iterations=5` (smoke), `best_model/` is never written (`eval_interval=10` default). In smoke mode the harness injects ONLY the `ppo.eval_interval=1` override into every ARM child training command (the shared supervised child additionally carries `--ppo-iterations 1` + `--skip-test-eval` — QA-007/MA-017, DRIFT-001 wording fix) (`PPOTrainer.best_val_reward` init is `-inf`, so the first validation always writes `best_model/`; `history.json` is saved unconditionally at training end; `ppo.save_interval=1` would waste a full model + optimizer-state write every iteration and is NOT injected), and after each run fails loud if the expected `<run_dir>/ppo_t5/best_model` checkpoint is missing. Child commands are constructed as argv LISTS executed with `shell=False` — never shell-string interpolation of config-derived values. Each child's stdout/stderr is tee'd to `<run_dir>/train.log`; a nonzero child exit fails the harness loudly with an error naming the run, the exit code, the log path, and the log tail; the harness prints a per-run progress banner (`[k/N] arm=<arm> seed=<s> started/finished, elapsed`).
  Entry: harness child-command construction (subprocess argv assembly), dry-run mode.
  Through: real argv assembly + real post-run checkpoint existence check.
  Exit: smoke argv contains `ppo.eval_interval=1` and NOT `ppo.save_interval=1`; argv is a list and no `shell=True` anywhere in the harness; missing checkpoint or nonzero child exit → raised error naming the run + log path.

- **R-012** [unit] (prepared-spec R-8 reuse): The harness's evaluation path calls `scripts.compare_policies.evaluate_t5_policy` and reuses `evaluation/metrics.py` + `evaluation/controls.py` bootstrap semantics — it must not reimplement episode rollouts or metric math. Enforced structurally: the eval stage is a thin wrapper whose test monkeypatches `evaluate_t5_policy` and asserts it is the sole eval entry point (no `TossupMCEnv` construction inside the harness module).
  Test: monkeypatched call-through assertion + a source-level assertion that the harness module does not import `TossupMCEnv`.

- **R-013** [integration] (added per RV-002 + RV-003 + UX-001 + UX-005 — preflight + resume): On startup, BEFORE launching any child, the harness runs a mandatory preflight: it resolves the persisted split artifacts itself and fails loud with actionable guidance ("run `scripts/build_mc_dataset.py --smoke` first", naming the missing path) when they are absent; assembles and validates EVERY child argv for the complete arm×seed plan up front (an arm-specific flag typo cannot cost the shared supervised phase); and prints the plan (runs, dirs, injected overrides, split source). `--dry-run` stops after the preflight with zero children launched. After each child run it asserts the run's `split_manifest.source == "persisted_artifacts"` (the silent random-split fallback invalidates provenance). The harness is idempotently RESUMABLE: a run is complete iff a completion marker (`<run_dir>/RUN_COMPLETE.json`, written by the harness only after child exit 0 + checkpoint check) AND `ppo_t5/best_model` + `config_used.json` + `split_manifest.json` exist (hazard arms also `hazard/best_model`); complete runs are skipped, marked `"resumed": true` in the report, and still subject to the full R-003 sidecar assertions (a stale dir from an older config fails loud rather than polluting the comparison); a git-SHA mismatch between a reused run and the current checkout is recorded in the provenance block and warned, not silently mixed. PARTIAL dirs (outputs without the marker) fail loud with instructions (delete the dir or pass `--force`); `--force` re-runs everything.
  Entry: harness planning stage against pre-created fake run outputs (with and without the marker); subprocess runner monkeypatched to count invocations.
  Through: real output-existence checks + real sidecar assertion path.
  Exit: complete outputs + marker → zero child invocations for that run + `resumed: true`; partial dir (no marker) → loud error with instructions; `--force` → re-invoked; missing split artifacts → actionable error before any child run; `--dry-run` → plan printed, zero children.

- **R-014** [integration] (added per UX-002 + UX-003 — per-run eval persistence, report-only, prune): Immediately after each arm×seed evaluation the harness writes `<run_dir>/eval_result.json` (the full R-005 metrics + the `return_runs` per-question records); the report-assembly stage reads EXCLUSIVELY from these per-run files, and `--report-only` reassembles the report + plot from existing run dirs without launching any training or evaluation. Fail-loud assertions may block the aggregate report but never delete or skip writing per-run eval artifacts. `--prune-checkpoints` (default off) deletes `iter_N/`, `epoch_N/`, and `training_state.pt` AFTER a run's `eval_result.json` exists, keeping `best_model/` + sidecars so the report stays regenerable.
  Entry: eval stage with monkeypatched `evaluate_t5_policy`; assembly stage from fixture run dirs.
  Through: real per-run JSON writes + real assembly reads.
  Exit: `eval_result.json` written per run before assembly runs; `--report-only` performs zero training/eval subprocess calls and produces report + plot; prune keeps `best_model/` + sidecars + `eval_result.json`.

- **R-015** [unit] (added per UX-006 — documentation): `AGENTS.md` gains a "Hazard efficacy harness" subsection documenting: the smoke and t5-base invocations, expected wall-clock + disk footprint, the output artifact layout (report, plot, per-run dirs incl. `eval_result.json` + `RUN_COMPLETE.json`), and the resume / `--report-only` / `--prune-checkpoints` semantics.
  Test: AGENTS.md contains the subsection with those elements (asserted at `/cverify`).

### Format pinning (AP-031 discipline)

The harness parses sidecar files produced by other components; the exact formats are pinned to their producers:
- `config_used.json` — resolved nested config dict PLUS the R-003 `hazard` block and top-level `seed`, producer `scripts/train_t5_policy.py::main` (`save_json(trainer.checkpoint_dir / "config_used.json", resolved_config)`); written under `<run_dir>/ppo_t5/`.
- `split_manifest.json` — fields `source, mc_path, {train,val,test}_path, {train,val,test}_qids, {train,val,test}_count, effective_*_ratio`, producer `scripts/train_t5_policy.py::_build_split_manifest`; same dir.
- `history.json` — list of per-eval dicts (`iteration, train_reward, ..., val`), producer `training/train_ppo_t5.py::PPOTrainer.save_history`.
- `hazard_history.json` — NEW producer added by R-010 in `training/hazard_pretrain.py::run_hazard_pretrain`; schema `{"steps": [{"epoch": int, "question_index": int, "loss": float}], "config": {"beta_terminal": float, "freeze_answer_head": bool, "ablation": str|null, "lr": float, "epochs": int}, "wall_clock_seconds": float}` — the top-level `wall_clock_seconds` is the HAZARD-PHASE wall clock (load + train + save; amended in QA fix round 1 (QA-006): the report's `hazard_compute.wall_clock_seconds` is sourced from it, never from the PPO-dominated child-total marker elapsed). The harness reads only through this pinned schema.
- Per-question runs — `evaluate_t5_policy(return_runs=True)` per R-002 (this spec is that producer's authority).
- `RUN_COMPLETE.json` — additive field `shared_supervised_weights_sha256` (string; the branch-point checkpoint's content sha256, stamped by the harness and asserted on resume) — amended in mini-audit fix round (MA-003). Markers are written atomically (temp + `os.replace`) and read through a typed reader — amended in mini-audit fix round (MA-015).
- `SHARED_SUPERVISED.json` — additive field `weights_sha256` (string; content sha256 over the saved shared checkpoint's model files, excluding the harness-written `split_manifest.json` sidecar; verified on every reuse) — amended in mini-audit fix round (MA-003).
- Report `hazard_compute` / `hazard_dynamics` blocks — additive fields `source_arm` / `source_seed` naming the single replicate they were read from — amended in mini-audit fix round (MA-010). `hazard_dynamics` additionally carries an additive `index_convention` string (per-position arrays are 1-indexed prefix positions; the endpoint's `runs[].buzz_position` source is 0-indexed) — amended in mini-audit fix round (MA-011).
- Report per-run rows — additive field `hazard` echoing the run's recorded `config_used.json` hazard block — amended in mini-audit fix round (MA-001).

## Won't Do

- **Expected Wins in the default report.** Requires an opponent model + `reward_mode="expected_wins"` wiring (`evaluate_all.py`-style `build_opponent_model_from_config`); explicitly out of the default path (R-005). An opt-in wiring is future work, not this feature.
- **Full-scale t5-large runs or any Device-2 execution.** This harness produces smoke (t5-small) + preliminary (t5-base) evidence on Device 1 (M3 Max/MPS) only; the definitive run is a Device-2 (RTX 5090) handoff.
- **Bitwise same-seed reproducibility on MPS.** MPS kernels are not all deterministic; the E-1 seed contract is "different seeds ⇒ different draws, split fixed", not bitwise replay.
- **A new `hazard:`/`eval:` YAML config section.** Knobs come from CLI flags + existing positional overrides (matches the bridge spec's Won't-Do).
- **`supervised-longer` as the compute control.** Weaker than the step-matched null-signal ablation (B=1-per-question steps aren't commensurable with supervised B=N steps); Arm C uses `shuffled_nll`.
- **Multi-question batching in the hazard loop / the loss `mask=` path.** Unchanged MVP B=1 (bridge spec Won't-Do stands).
- **Touching vendored `.correctless/hooks|scripts/*.sh`.** Feature/eval code goes in `scripts/`, `training/`, `evaluation/`, `tests/` only.

## Risks

- **Smoke test set is ≈8 questions (global `max_questions=50` cap)** → any smoke-scale metric delta is noise. Mitigated: R-007 hard-gates significance labels; smoke is declared plumbing + training-dynamics evidence only.
- **Arm C's shuffled objective may actively harm the stop head (anti-signal), not just be neutral.** Accepted: C is a compute control, not a second treatment; interpretation documented in the report (C≈A ⇒ B's delta is signal; C≪A ⇒ hazard-phase compute itself is disruptive and B-vs-A must be read against that).
- **MPS wall-clock at t5-base** (PPO dominates; hazard phase itself is ~seconds). Mitigated: smoke first; t5-base runs may reduce `ppo.iterations`/question count, with the actual scale recorded in the report `scale` block (R-009) so claims stay scoped.
- **T5 dropout is active during the hazard phase (`model.train()`)** → per-step loss is noisy; loss-decrease evidence uses epoch-half means (R-010), not step monotonicity. Accepted. (The R-010 stop-prob PROBE runs in `eval()` mode so the shift measurement itself is dropout-free.)
- **Shared supervised checkpoint fixes the supervised-phase RNG** → supervised-phase variance is not sampled; seeds vary hazard/PPO only. Accepted: that is the point of the paired design (isolates Phase-1.5+PPO effects); stated in the report.
- **A degenerate shared supervised checkpoint (never/always buzzes) would flatten all arms.** Accepted with visibility: R-005's `policy_buzz_rate`/`forced_commit_rate` per run make this diagnosable from the report rather than invisible.
- **`torch.load` (pickle) on checkpoints** — in-pipeline trusted artifacts only, same acceptance as the bridge spec (F4). Not user-supplied.
- **Two runs sharing one machine could interleave badly (thermal/memory)** → arms run sequentially, never in parallel, by harness design. Accepted (runtime cost).
- **Resume + config drift**: a resumed run dir created under an older config could poison the comparison — mitigated by R-013 running the full R-003 sidecar assertions on resumed dirs too.
- **Disk footprint**: a full harness run writes O(10) full T5 model copies (tens of GB at t5-base) under a Dropbox-synced tree (`.gitignore` routes `checkpoints/` through Dropbox sync). Mitigated: R-011 injects only `eval_interval=1` (no per-iteration full saves), R-014's `--prune-checkpoints` reclaims space once `eval_result.json` exists, and the report `scale` block records measured disk usage.

## Open Questions

- (none blocking) Knob-sweep breadth (`--beta-terminal` 0.5/1.0/2.0 × `--freeze-answer-head` on/off) is an experiment-protocol decision made at run time from observed wall-clock; the harness supports extra B-variants via repeatable variant flags, so no spec change is needed either way.
